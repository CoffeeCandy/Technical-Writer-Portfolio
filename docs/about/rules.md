# 本博客文档格式规范
* 本节用于规范 MkDocs 使用手册的整体文档结构与格式风格，确保在多人协作、多页面维护的场景下，文档在结构、样式和可读性上保持一致，提升整体维护效率与阅读体验

 

## 一、文件与目录命名规范

* 文档源文件统一使用 **小写字母 + 中划线（kebab-case）** 命名
  例如：`getting-started.md`、`theme-configuration.md`
* 不使用空格、中文或特殊字符作为文件名
* 目录层级不宜超过 **3 级**，避免过深嵌套
* 每个目录应具备明确的功能或主题含义

该规范有助于提升跨平台兼容性，并避免 URL 编码与路径解析问题。

 

## 二、页面基本结构规范

* 每个文档页面应遵循统一的结构组织方式，以便读者快速理解页面内容与定位关键信息。
```text
    # 页面标题
    页面简要说明，用于概括本页内容与适用场景。
    ## 按照步骤或者重要性进行模块的展开
```
 

## 三、标题层级规范
* 每个页面只允许存在 **一个一级标题（`#`）**
* 标题层级必须连续，不允许跳级
  （例如：`##` 后不可直接使用 `####`）
* 标题应准确描述其下内容，避免使用泛化表述
  （如“说明”“介绍”“其他”等）

标题的主要作用是 **组织信息结构，而非装饰页面**。



## 四、正文与段落规范

* 正文段落不宜过长，建议 **3–5 行**为一个自然段
* 每个段落应只表达一个核心观点
* 关键概念、重要结论可使用 **加粗** 进行强调
* 避免大段连续文字，必要时使用列表或分点说明
* 文本不要顶格写,使用无序列表,保证文档清晰直观
该规范有助于提升扫描阅读与快速理解能力。



## 五、代码块与命令示例规范

* 所有代码块必须指定语言类型
  例如：`bash`、`yaml`、`json`
* 示例命令应保证 **可复制、可执行、可验证**
* 代码块前后需配合必要的说明文字，避免孤立展示
* 当有代码块的时候,本小节不用有序列列表,否则序号会乱套
* 所有的代码块前都应有一个Tab
示例：

```bash
    mkdocs serve
```
所有示例均应以读者能够直接实践为原则。

---

## 六、提示块（Admonition）使用规范
mkdocs文档中可使用提示块增强关键信息的可见性，但应避免滥用。

建议使用场景如下：
* `note`：补充说明或背景信息,
* `tip`：使用技巧或推荐做法
* `warning`：可能导致配置错误、数据丢失的风险提示,可用⚠️ 代替

## 七、可维护性说明

统一的文档格式规范有助于：

* 降低多人协作成本
* 提升文档 Review 效率
* 支持后续版本迭代与自动化检查
